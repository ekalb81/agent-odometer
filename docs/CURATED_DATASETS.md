# Curated local evaluation examples

Set an explicit **Accepted** or **Rejected** human outcome in session organization, then choose **Curate reviewed example**. Select one to four conversation records, name the example, optionally add a rubric and exact phrases to redact, and build a preview. Review the displayed text and check the review box before saving. Changing an input requires a new preview. **Analytics → Outcomes → Human outcomes → Review local dataset** opens the saved collection.

Rust produces both the preview and saved content. It keeps user/assistant text, excludes tools, reasoning, attachments and unknown records, applies the transcript export redaction policy and your exact phrases, then limits each selected record to 3,000 UTF-8 bytes. Truncation is labeled. Automatic redaction is heuristic: review the exact preview for private material it missed. Organization notes, tags, raw JSON and source paths are excluded. Limits are 64 examples, four records per example and 16 KiB per stored example. Previews expire after five minutes; only the latest eight remain available.

Each example has a stable numeric ID, its last-edited dataset version, captured expected outcome, capture time, provider, opaque source anchors, source fingerprint and local content hash. The hash detects changes; it is not a signature. Editing replaces an example under its ID and advances the dataset revision. Add, edit and remove operations check the revision, so competing changes require a reload. The content-free change journal keeps 4,096 revisions and reports its earliest retained revision. ID/hash entries explain membership changes without retaining old text. Selected examples are not a representative denominator or proof of model performance; no evaluation or model execution is performed.

Preview and save each verify exact source records and the current human-outcome revision. Appends preserve unchanged anchors; missing or replaced records cannot be substituted. Available archived/imported sources use the same inspector reader. Previously saved minimized examples remain usable when their source is unavailable; refreshing them requires an available source. Preserved recovery backups are labeled unrestored and are not silently imported.

**Remove reviewed example** deletes its current stored content and keeps a content-free removal entry. Reviewed history purge removes examples belonging to the purged session, invalidates open previews and advances the dataset revision. Earlier exports and preservation backups are independent files; deletion does not claim forensic erasure of SQLite pages or backups.

**Export reviewed dataset JSON** uses the native save dialog and exports the exact collection, revision, provenance and retained journal. Ordinary usage reports and transcript exports omit the collection. This feature is fully local, adds no network permission, uploads nothing and invokes no model.

Native export is version-checked after the save picker closes, using the reviewed backend digest. A short immediate history transaction serializes final revalidation and atomic file publication with edits, removal and purge. No history lock spans the user-controlled picker. If content changed while choosing a file, export rejects stale bytes and leaves the destination unchanged; reload and review before retrying. A successfully completed explicit export remains an independent file if a later purge occurs.
