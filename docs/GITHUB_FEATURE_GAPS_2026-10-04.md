# GitHub feature comparison — 2026-10-04

Odometer already covers much of the usage-dashboard category. The strongest remaining opportunities are deeper investigation of individual sessions, better retrieval and organization of past work, and richer presentation of existing data.

**Baseline:** Odometer v0.8.20, commit [`d1f011d`](https://github.com/ekalb81/agent-odometer/commit/d1f011da01b17289737d94e4e1ce9acf7df61476). Reviewed the current README, production source, headless documentation, sync ADRs, and open GitHub roadmap issues. External features below were verified in current primary project READMEs/docs; the other applications were not installed or runtime-tested. This is a feature comparison, not a quality, security, or performance ranking.

**Meaning of “missing”:** no implementation was found in the relevant current production source and exposed commands/UI. “Partial” means Odometer has a related foundation but lacks the specific capability described. These are bounded source-audit findings. Documentation alone was not used to establish absence: parts of the architecture document lag current Gemini, ledger, and headless functionality.

**What I would build first**

1. **Conversation search plus bookmarks/notes.** Make past agent work easy to retrieve and retain useful findings. Start by searching the retained turn messages; explicitly indicate when original transcript content is unavailable or was never retained. Extend to optional tool-content indexing only with a defined local data boundary.
2. **An on-demand session inspector.** Open complete local transcript records, specialized tool results, and parent/child execution context from an expensive or failed turn. Preserve the lightweight session-summary contract; do not add entire transcripts to list responses or aggregate exports.
3. **Context/compaction explanations.** Connect a context increase to available record evidence. Any reconstructed token attribution needs an estimate label and method; provider-reported aggregate usage should remain the accounting authority. The competitor's claimed precision has not been independently established here.
4. **Finish the existing presentation work in #48.** Calendar drill-down and a more useful tray reuse current ledger/query foundations. Keep activity volume separate from productivity.
5. **Finish consented live quotas in #43** for users who need current allowance information. Preserve the separation between account state and historical transcript accounting.

For measuring whether a workflow change helped, I would add explicit accepted-task outcomes and repair effort before recommending a “productivity score.” Cost, throughput, Git retention, and successful delivery answer different questions. This is a product recommendation, not a claim that any surveyed app already measures Odometer's desired end-to-end outcome.

**Fit and existing decisions**

- Items 1–6 are the closest extensions of a local analysis companion. A source transcript may be missing even when Odometer still has a durable summary; a richer viewer must preserve that distinction.
- Remote collection, checkpoint writes, and evaluation execution expand the product's operational scope. They are useful comparisons, not features authorized for implementation by this research request.
- Live polling, service status, and widgets are existing roadmap residuals, not newly discovered unstarted foundations. Live provider status is another documented gap in [#48](https://github.com/ekalb81/agent-odometer/issues/48).
- Broader adapter coverage is a real gap, but Odometer [documents evidence-based objections](https://github.com/ekalb81/agent-odometer/blob/d1f011da01b17289737d94e4e1ce9acf7df61476/README.md#first-run) to Cursor, Copilot, and OpenCode. Another project's support claim does not establish measured-token parity or remove those objections. A fresh source-format investigation would be needed.
- Tokscale's public leaderboard is a comparison point, not a recommended addition. Odometer's [sync/team decision records](https://github.com/ekalb81/agent-odometer/blob/d1f011da01b17289737d94e4e1ce9acf7df61476/docs/adr/README.md) are design-only; the roadmap preserves the anonymous-leaderboard no-go. There is no shipped cross-device sync or team aggregation.
- A transcript export with redaction preview would be my adaptation of the export tools, not a verified redaction capability of those tools. The `claude-code-transcripts` README currently warns that its web-session commands are broken; the local-file conversion workflow is the relevant reference.
- Existing budgets, ordinary subagent support, Gemini support, project grouping, CSV/JSON/Markdown metrics export, CLI/statusline/MCP, instruction inventory, tool analysis, and safe history rebuild must not be listed as absent. The outstanding integration work is guided setup and real-client verification in [#57](https://github.com/ekalb81/agent-odometer/issues/57).
